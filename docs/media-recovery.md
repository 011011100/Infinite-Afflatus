# 素材检查与原文件恢复

更新时间：2026-10-04。

项目内素材为受管副本。主画布和镜头素材组仍引用原素材 ID；恢复文件不改变画布位置、组合顺序、裁剪、文本覆盖、标签或生成参数。

## 入口与检查层次

打开项目后自动检查已登记原素材的位置与大小，顶栏「检查项目素材」显示异常数量。进入弹层可查看素材名称、项目内位置及具体问题，或执行完整内容校验。

- 位置检查：检查受管路径、普通文件类型和大小，不读取全部媒体。它不能确认同大小文件内容一致。
- 完整校验：逐一核对原记录的大小及 SHA-256，支持进度和取消。内容一致不代表编解码器一定支持播放。
- 取消或失败保留上一份完成的报告。位置检查不能清除此前已确认的内容变化，完整校验通过后才消除该提示。
- 项目数据库缺失、损坏或版本不支持时明确失败，不返回空报告或创建空库。

## 恢复规则

缺失素材显示「找到原文件」，由原生文件选择器选择文件。只有大小与 SHA-256 完全一致才接受，即使名称相同也不能替换为另一份内容；已有目标文件一律不覆盖。内容被改写的文件应先移出项目保留，再选择原文件恢复。

恢复先复制到应用数据目录的独立暂存区并流式校验，然后在项目目标目录生成临时副本、再次校验并原子发布。提交前重查项目、父目录、素材记录及文件身份。项目 SQLite 不写入任何恢复字段，素材 ID 与相对路径保持原样；成功后只刷新媒体 URL 和解码缓存，不重挂画布，避免丢失正在编辑的草稿和会话撤销历史。

检查与恢复使用同一写入队列，避免与项目迁移交错；流式读取每 256 KB 检查取消。取消、离开页面和退出也会使尚未完成的文件选择失效。发布是提交点，发布完成后的取消不删除已恢复的正确文件。临时文件按登记的路径、设备号与 inode 清理；应用重启只清理仍匹配的临时文件，保留用户替换的文件。

当前原子发布依赖目标磁盘硬链接。不支持的文件系统会明确失败；用户可关闭应用，将原文件手动复制到提示的项目内位置，再打开应用完整校验。不能降级为可能暴露半份素材的直接覆盖复制。素材完整后可使用已有迁移功能换到支持的磁盘。

## 已验证范围

核心自动测试包含真实文件的丢失、同大小改写、错误内容拒绝、取消、发布前取消、路径链接、迁移排队和重启清理。固定历史升级回归包含旧项目包导入；不更改既有历史基线。

macOS 上已用真实 Electron 的构建产物、preload 与 IPC 验证：打开包含缺失合成视频的项目，自动提示异常，经界面选择原文件恢复，缩略图重新读取，媒体字节与原项目数据库保持不变。文件选择器在测试中定向到隔离合成文件，不代表人工操作原生选择器。独立渲染回归验证 StrictMode 自动检查、修复不打断无关组合播放、相关修复保留位置／暂停／静音，以及文本恢复保留编辑覆盖与撤销历史。

上述不代表 Windows 桌面、正式安装包或云端 API 已验证。

## 实现边界

- 不提供任意换源或重编码替代，避免改变现有裁剪和镜头引用语义。
- 不自动扫描用户磁盘寻找同名文件，不修改用户选择的原文件。
- 原保存盘离线、整个项目目录移动或数据库损坏仍需单独的项目库恢复流程。有效项目包可从首页导入为独立项目；不覆盖损坏目录。
- 代理是可重建缓存，本检查针对已登记的原素材，不将代理缺失当成原素材丢失。
