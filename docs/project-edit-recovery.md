# 项目名称与裁剪恢复

项目改名和视频裁剪继续使用原来的入口。恢复副本在后台保护已输入的项目名称，以及松手、键盘微调、恢复原片、撤销／重做后提交的裁剪范围。它与镜头工作区恢复并存，不改变主画布、组合顺序或源视频。

## 页面行为

- 改名弹窗中的原始输入会保护，包括暂时清空的输入框。点击「保存」仍会校验名称；恢复只填回输入框，点击保存后才改名。取消等候本次保护结束，精确清理本流副本；清理失败留在可操作的弹窗中，可重试或导出。
- 裁剪松手后先保护完整目标范围，再串行保存。保存失败恢复已保存的预览，保留刚才的修改供重试；保护失败也不会把新裁剪标成已保存。正在拖动、尚未松手的预览不纳入崩溃恢复。
- 再次打开项目时，存在恢复副本才显示提示。名称提供「继续修改名称」；裁剪显示片段及范围，点击「恢复并保存裁剪」才提交。当前内容已经等于目标时可「确认已保存」，不重复修改数据库或增加撤销步骤。
- 当前名称输入、未保存裁剪、裁剪手势或画布保存尚未结束时，不能用另一份恢复副本覆盖它们。恢复期间暂停相关编辑，返回首页和原生关闭等候完整恢复及页面刷新。
- 裁剪恢复在当前会话加入一个撤销步骤，原有历史保持；不恢复上一进程的撤销栈。冲突或损坏的副本保持原文件，可导出可读取内容供救援。

## 持久化与确认

`userData/project-edit-drafts/<projectId>.<sessionId>.json` 使用独立的 v1 格式。一次名称编辑和每张卡片的裁剪分别使用独立流，记录单调递增的 `seq`；同一流串行保护，旧确认不能删除较新的输入。`workspace-drafts` 的 v1 镜头格式保持不变。

每份记录包括项目身份、原内容、完整目标和必要的已提交内容。名称保留未经裁切的输入；裁剪保存完整卡片及按播放顺序排列的素材元数据。文件写入、同步和发布完成后才确认保护。单文件上限 16 MiB，目录上限 2048 个文件、256 MiB；损坏文件、未知版本、符号链接与身份变化均拒绝覆盖或清理。

显式恢复在实际 SQLite 事务中再核对原名称或完整卡片、素材 ID／路径／哈希／大小等元数据，只改变该名称或该卡片的裁剪。其他卡片、视口、镜头工作区和素材文件保留。遇到变化保留副本，不用旧范围覆盖新的视频组合。

保存成功但回执丢失时，只接受与已保护提交完全匹配的项目读取结果。当前窗口中还须通过其他编辑器的恢复检查，之后才认领提交、推进撤销记录并重试后续裁剪。重开时可以从已确认的提交继续恢复后续目标；不会把一次失败回执当作无限重放的授权。再次提交名称前，先核对上一次未确认提交的实际名称并保护新的基线，因此连续丢回执仍可继续输入。项目事务已经确认成功时，单独清理副本失败不会被误报为保存失败；剩余副本可再次确认清理。

## 救援文件与边界

名称或裁剪的只读救援文件扩展名为 `.afflatus-edit-draft.json`。保护失败时也可导出仍在内存中的完整目标。已有目标文件不覆盖；此文件不是 `.afflatus` 项目包，不含原媒体、镜头工作区或撤销历史，当前不提供救援文件导入。

独立副本不能保证硬件断电零丢失。应用数据库损坏或整个保存盘离线时，仍须先通过启动恢复入口恢复原库。普通素材标题的行内输入、主画布移动／拼接的未提交手势，以及跨重启撤销历史不在本格式范围。

## 验证入口

原生文件与 SQLite 回归在 `tests/project-edit-draft.test.ts`；名称和裁剪队列测试核对顺序、失败重试、旧回执及确认边界。隔离 React 回归使用实际页面和模拟桌面接口，与生产 Electron 的强杀／重开、磁盘故障和真实媒体手势测试分别记录。固定历史写入基线随 `pnpm test:upgrade` 验证，不能用当前代码重新生成旧数据代替。

固定原生写入基线为 `1f77f143f909940571a337adcc787b301933bd86`；名称／裁剪的普通未提交与 A 已提交、B 待提交四种历史场景都经两个新进程重开核对，详见 [升级测试](data-upgrade-testing.md)。
