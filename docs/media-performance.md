# 大项目媒体资源

主画布仍保留全部卡片、片段按钮和原有布局，继续使用现有平移、框选、横向滚动、拼接、局部拆分与撤销。此项优化控制媒体读取和位图占用，不改变项目数据格式，也没有增加常驻按钮或移除画布节点。

## 读取与释放

- 主画布首帧与完整组合的时长／尺寸读取共用最多三个并发槽。当前可见、键盘焦点与正在按住的卡片优先于预读；相同资源共用工作，各消费者分别取消。已取消的底层读取真正结束后才释放槽。
- 共用可见性观察器识别视口及 160 px 邻近范围，并服从组合横向滚动容器的裁切。冷的离屏卡片不开始解码，显示 canvas 初始像素尺寸为零。
- 离屏 600 ms 后释放该卡片的帧引用与显示像素，覆盖原有约 440 ms 的拆合过渡。焦点和主指针按住期间保留；取消、松手和失焦解除保留。仅选中不能固定全部离屏素材。
- 拆合动画保留完整的片段几何与顺序，只对原来可见的片段采集 FLIP 动画状态，避免为长横排逐一强制布局。新出现的原离屏片段在目标位置显示，原本可见的片段继续原有过渡。
- 全窗口播放器或镜头子画布覆盖主画布时停止缩略图请求，并清空背景显示像素。返回与拆合后的新卡片优先同步使用仍在缓存中的首帧。改名、设置弹窗与保存中的操作锁不清空仍可见的背景。
- 首帧缓存以 `宽 × 高 × 4` 计成本，最多保留 64 MiB，按最近使用淘汰。淘汰只解除缓存引用，不清空其他卡片仍在使用的 canvas。该预算不包括可见显示副本、过渡中的引用、浏览器待回收对象、视频解码器或进程其他内存，不能当作整个应用的内存上限。
- 完整组合读取 `loadedmetadata` 提供的时长与尺寸，使用独立小缓存，不创建或保存每段首帧。轨道胶片仍使用已有的可见范围取帧与独立缓存，播放双缓冲和胶片解码不算在上述三路首帧／元数据调度中。

资源键继续包含项目、素材 ID、源文件哈希与媒体修复版本。错误可以重新读取；清空或取消后的迟到结果不能覆盖新请求。底层媒体读取结束、失败、超时或取消后均移除媒体源。

## 验证口径

Node 回归检查共享并发、独立取消、优先级、失败重试、LRU 成本和清空后的迟到结果。隔离 React／Electron 夹具检查真实可见性、横向裁切、焦点与按住、热缓存重挂载、遮挡以及卸载；模拟时序断言与真实媒体读取分别记录。

生产压力脚本使用独立应用资料目录和固定的合法合成 H.264 视频，调用实际主进程、preload、SQLite、页面与 Chromium 媒体管线。测试素材为 640×360、12 fps、8 秒、无音频的纯色片，SHA-256 为 `80d2a1cc9595e83db05350dd920127cf79ad1bd88792234f7d1a14bdbb288fb9`。每份素材有独立 ID 与文件；固定字节随测试源码保存，不依赖本机编码器，不使用用户素材。

```sh
pnpm check
pnpm build
pnpm test
pnpm test:browser
node --import tsx tests/browser/media-resource-profile.mjs --count=100 --label=current --resource-limits
node --import tsx tests/browser/media-resource-profile.mjs --count=1000 --label=current --resource-limits
```

脚本记录主画布首屏、实际平移并返回、长组合横向滚动、完整时长、真实鼠标裁剪与撤销、中间片段拆分与撤销，最后逐文件核对源素材哈希。输出报告、截图、Chromium Media 原始事件及 Electron 进程工作集。

媒体元素的源活跃数量、CDP 媒体管线、canvas 像素与进程工作集各自计量。CDP 可以说明实际播放器及解码器名称，不能代表操作系统全部硬件解码器占用。canvas 像素可能包含等待垃圾回收的对象，不能直接充当 RSS。首屏和内存数值只作同机对照，不设跨机器脆弱阈值；并发与离屏显示释放必须满足明确断言。

此场景不代表 4K／HDR、多编码格式、长时间剪辑或所有硬件兼容性。仍保留全部 React Flow 节点和片段 DOM，大规模节点布局、复杂素材与长时间操作需要独立验证。

## 本机对照记录

2026-10-05，在同一台 macOS 上使用上述固定素材，100 个视频包含 20 个独立卡片与一个 80 段组合。下表是单次带观测的生产运行，不能作为所有机器的性能承诺。

| 指标 | 改动前 | 改动后 |
| --- | ---: | ---: |
| 可见首屏全部画好 | 626.1 ms | 263.8 ms |
| 管理范围内媒体源活跃峰值 | 100 | 3 |
| 有解码器标识的 CDP 管线峰值，含退出过程 | 100 | 3 |
| 主画布稳定时显示 canvas 像素 | 18,662,400 | 2,799,360 |
| 同时观察到的总 canvas 像素，含离屏对象 | 37,324,800 | 5,598,720 |
| 渲染进程工作集峰值 | 416,336 KiB | 270,896 KiB |
| GPU 进程工作集峰值 | 133,856 KiB | 131,488 KiB |
| 80 段组合编辑就绪 | 79 ms | 188 ms |

旧版在主画布已经全量读取首帧，新版第一次打开组合补读了 70 段元数据且没有抽取首帧，因此有额外的编辑就绪等待。两版均完成 640 秒完整时长、平移返回、组合滚动、真实裁剪与撤销、局部拆分与撤销，100 份源文件哈希保持。新版拆分至保存 23 ms，撤销至保存 61 ms，另通过离屏显示归零和全窗口编辑时背景显示归零断言。播放器／胶片独立管线峰值均为 3，不和主画布调度上限混为一谈。工作集、尤其 GPU 工作集会随运行波动，不承诺固定降幅。

旧 renderer 文件 SHA-256：`4d0ebd9c1922859a04338c22c0e89155b7a717c9064202bac4cdccd2aedb1e58`；新版：`7f0f5f6c4a0dc92ab04c6f5a3d688a8f8fa656e48c4dc2028d8ccadba7f06c42`。两端 CI 将生产报告、合成素材界面截图与原始 Media／进程记录另存为媒体资源构建物；不收集用户项目或测试数据库。

同一新版另通过 1000 个视频（200 个独立卡片＋800 段组合）的完整压力场景：首屏 508 ms，800 段共 6400 秒，编辑就绪 2210 ms；拆分至保存 336 ms、撤销至保存 458 ms。全部源文件哈希保持，首帧／元数据媒体源峰值与独立 CDP 管线峰值均为 3，首次稳定主画布显示像素仍为 2,799,360。全窗口编辑清空主画布显示位图，711 次实际元数据读取没有视频到 canvas 的抽帧。

长组合实际逐窗浏览了 128 个不同首帧，实测每帧 576×324，累计访问像素成本 95,551,488 字节，超过缓存预算。回到首片后再次触发真实 `loadeddata`，证明旧帧已淘汰并重新读取；缓存精确预算与共享引用不被清空另由单元回归核对。该次渲染进程工作集峰值 561,440 KiB、GPU 121,344 KiB，说明全部 DOM、播放与浏览器本身仍有额外占用，不能把 64 MiB 缓存预算当成应用总内存。

长组合拆合检查保留原 15 秒 CDP 响应上限和全部内容断言。压力排查中收窄了产品的 FLIP 采样范围，也将探针对像素的全表扫描合并到微任务；最终前后对照使用相同观测器，避免把测试自身的反复扫描误当作产品性能。

早期 CI 的冻结已通过主进程原生调用栈定位为测试启动竞态：探针在首次 `loadFile` 完成前执行 `Page.reload`，引起 `ERR_ABORTED` 与应用退出请求；保存保护等待 30 秒后显示原生错误框，阻塞自动化。测试现在先等原生加载完成、文档 complete 和首页就绪，再安装探针并刷新；保留产品原有退出与保存保护，断言加载失败、关闭及退出请求均为零。1000 片场景额外保持存活超过 31 秒并检查响应，额外停留不计入首屏或编辑耗时。上表与 1000 片数据均在修正启动顺序后重新测量；这次冻结不能归因为已证实的动画死锁。
