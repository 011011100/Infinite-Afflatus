# 播放与简单时间裁剪

更新时间：2026-09-30。

## 已实现

卡片唯一播放入口与双击均进入占满应用窗口的编辑页；不使用预览弹窗，也不强制切换系统全屏。主画布保留挂载并暂时不可交互，返回后恢复原位置、选择和焦点。

- 上方画面，下方只有一行控制栏：左侧播放／暂停与当前时间／总时长，右侧静音、恢复原片与轨道缩放；不展示文件名和片段序号，不另起一行重复片段数量和总时长。
- 一条按有效时长比例排列的时间轨道，有秒数刻度、缩略图和播放指针；可以横向滚动、缩放和跨片段定位。轨道卡片不叠加文件名、编号和文字底部遮罩，片段名保留在无障碍标签中。
- 播放指针的拖动输入按显示帧合并，指针和时间读数直接反映目标位置，视频片段标记反映实际已准备的画面。同段定位只保留一个正在解码的请求与一个最新目标，避免密集修改 `currentTime` 打断解码；跨段不等待旧段加载，松手立即优先定位最终时间。暂停拖动时保留两个已加载片段，反向拖回不重设 `src`；继续播放才预加载下一段，复用旧片段时仍定位到正确入点。
- 时间尺在带秒数的长刻度之间添加短刻度，随缩放划分为 5 或 10 小格，间距至少 10 像素；10 小格时用稍长的中间刻度区分半格。细刻度用 CSS 重复渐变绘制，不为每条线增加 DOM 节点；与裁剪后的时间原点及播放指针对齐。时间尺按实际轨道宽度延伸到片段后的空白区域，缩放和裁剪时同步更新；不改变组合时长，定位仍限制在有效视频范围内、不吸附。
- 不再单独展示选中片段的名称、入出点与保留时长栏。「恢复原片」位于合并后的控制栏右侧、缩放按钮左边，仅恢复选中的片段。缩放使用减号／百分比／加号，范围为 50%–600%，每次调整 25 个百分点；拖动裁剪手柄期间禁用缩放。
- 鼠标悬停片段时两侧手柄用 150 毫秒淡入，移开淡出；选中不让手柄常驻。直接拖动手柄自动选中对应片段并设置入点与出点，拖动即时预览边界，松手保存一次；拖动期间和键盘聚焦手柄时保持可见，键盘聚焦及减少动态效果跳过淡入淡出。显隐动画只作用于透明度，不改变手柄位置。入点手柄移动左边缘并固定右边缘，出点手柄移动右边缘并固定左边缘；相邻片段随对应一侧移动，仍连续播放。轨道比例只随主动缩放或窗口尺寸变化，松手保存不重新缩放或跳位。Esc、窗口失焦、窗口缩放或取消指针会放弃草稿。
- 手柄方向键微调 0.1 秒，Shift + 方向键调整 1 秒；范围约束到源视频，至少保留 0.1 秒（不足 0.1 秒的源片保留整段）。可以向外拖回或「恢复原片」。
- 鼠标拖到源片起止点或最小时长限制后，继续拉动会让当前白色拖柄轻微弯曲并高亮内侧边缘，阻力递增、形变上限约 4 像素；松手用约 200 毫秒恢复。只改变拖柄与高亮，不改变真实卡片边界。反向移动立即恢复裁剪，新的拉动可打断回弹。减少动态效果时只显示高亮。边界外重复移动不反复触发视频定位，未修改范围不产生保存或撤销步骤。
- 缩略图以源素材起点为基准绘制，入点变化时按源时间偏移裁去左侧画面，不从新的左边缘重新铺图。两端拖柄为卡片内部的细长白色圆角竖条，不再突出蓝色块；透明命中区向外保留 8 像素容差、向内最多到片段中点，极短片段也不重叠。一次裁剪手势期间保留轨道达到的最大滚动范围，松手后按有效内容收敛，不累计整次编辑会话的空白范围。
- 撤销／重做使用画布共用会话历史、最多 50 步；编辑页仅处理当前组合的裁剪，不跨入之前的画布结构操作。快捷键沿用设置并区分 macOS／Windows。
- 每次松手进入串行保存队列，通过原有项目 IPC／迁移闸门保存 SQLite；保存期间手柄仍可继续操作，较早的保存回执不会覆盖新的拖动。失败放弃依赖该次保存的后续草稿，恢复最后已保存范围并提示。迁移时允许播放，禁止编辑。返回画布后卡片时长同步裁剪长度。

## 数据与模块

`CanvasCard.trims` 是可选的 `assetId -> { start, end }`，单位为源视频的秒数。未提供表示完整源片。沿用画布 version 1 和 SQLite 容器格式，旧项目自然兼容；主进程验证有限数值、非负入点、出点大于入点、素材归属，并将裁剪纳入过期写入比较。渲染进程获取媒体时长后再约束到真实范围。

- `shared/canvas/trim.ts`：入出点与范围约束；`model.ts`：格式和过期写入校验；`operations.ts`：拼接合并裁剪映射、拆分分配给对应连续组。
- `editor/sequence-editor.tsx`：页面与共用按钮；`use-sequence-editor.ts`：草稿、选中片段、保存和快捷键。
- `editor/trim-save-queue.ts`：连续裁剪的乐观状态、顺序提交和失败恢复；`use-trim-gesture.ts`：稳定的指针捕获、拖动基准和取消。
- `editor/sequence-timeline.tsx`：刻度、定位与手柄展示；`filmstrip.tsx`：绘制可见区域的分时缩略图；`timeline.ts`：组合时间与源时间换算。
- `editor/filmstrip-layout.ts`：源时间锚点、缩放采样密度及可见范围；`filmstrip-cache.ts`：串行任务、过时取消及最多 192 帧的缓存；`filmstrip-decoder.ts`：独立视频解码器，生成不大于 192×128 的帧，不导出像素或重写素材。可见画布按设备像素密度绘制，不把超长轨道压缩进一张低分辨率画布。
- `editor/trim-auto-scroll.ts`：左右对称的边缘速度、快速拖动的可视范围补偿和素材范围约束；`use-timeline-viewport.ts`：裁剪预留空间、坐标基准及归一化滚动量，避免预留空间被误算成裁剪输入。
- `editor/timeline-ruler.tsx`：长短刻度、标签与随缩放调整的刻度密度。
- `editor/use-ruler-seek.ts`：播放指针捕获、逐显示帧采样、松手精确定位，以及失焦、取消和卸载清理。
- `editor/sequence-controls.tsx`：播放、组合时间和静音，与 `timeline-toolbar.tsx` 的恢复原片、缩放按钮共用一行；缩放由编辑页统一管理并传给轨道。
- `editor/trim-handle.tsx`：内置拖柄、命中区域与键盘微调。
- 轨道卡片的选中与键盘焦点描边绘制在缩略图的同一圆角裁切层内，避免独立外描边在圆角处露出浅色接缝；拖柄命中区保留在外层，不受内容裁切影响。
- `editor/trim-drag.ts`：增量裁剪与边界阻尼，保留亚毫秒输入并消除反向空拖；`use-trim-boundary-feedback.ts`：SVG 拖柄形变、GSAP 回弹与减少动态效果。
- `editor/use-sequence-frames.ts`：复用项目缩略图缓存读取时长，限制新解码并发。
- `playback/sequence-playback.ts`：双缓冲、播放时钟、出点切换、暂停和取消；`seek-video.ts`：可取消的解码定位；`use-sequence-playback.ts`：React 生命周期。修改裁剪范围不重建播放器。
- `playback/adaptive-playback.ts`：原片／代理两层播放器复用、150 ms 停留与松手恢复原片、就绪帧切换、过时恢复取消与原片降级。代理不播放音频。
- `main/media/proxy-service.ts`：串行转码、暂存及迁移协调；`transcode-proxy.ts`：FFmpeg/FFprobe 调用和时间范围校验；`proxy-work.ts`：按登记身份清理暂存文件。
- `playback/seek-scheduler.ts`：同段解码串行并合并过时目标，切段／松手优先，取消后的旧任务不得清除新目标或恢复排队定位。播放指针和裁剪预览共用此调度。

源文件不重写。播放与编辑页现可单独导出新视频，见 [本地创作交付](local-delivery.md)。轨道图片是按缩放密度采样的源片画面，主要辅助内容定位，并非逐帧图谱；尚未解码的位置保留中性底色。边界控制是浏览器预览精度，尚不承诺逐帧编辑或预览音频无缝。中间切开、片段重排和画面裁切仍未实现；FFmpeg 导出按保存的入出点执行并单独验证。

### 2026-09-30 播放指针定位性能

- 相关自动测试 34 项通过，新增覆盖：80 次目标输入只执行当前和最后目标、两个暂停片段往返 12 次各加载一次、跨段取消慢加载、松手优先、播放使用最新待定位时间、关闭后不恢复旧队列，以及已播放缓冲复用后回到正确入点。
- 浏览器对照使用当前播放器与 `31774c9` 的旧播放器，同一份 FFmpeg `testsrc2` 生成的 1280×720、30 fps、8 秒 H.264 视频（`libx264 -preset veryfast -g 120`）。每轮以约 8 毫秒间隔提交 120 个位置，实际输入阶段约 1.1 秒，三轮交替新旧顺序；没有模拟解码延迟。以 `requestVideoFrameCallback` 的媒体时间与可见播放器切换记录不同画面的呈现，包含最终位置收敛阶段，不能当作视频的编码帧率或所有素材的性能保证。

| 场景 | 旧逻辑，每轮呈现新画面 | 新逻辑，每轮呈现新画面 | 松手后目标画面显示（旧 → 新） |
| --- | --- | --- | --- |
| 同段连续定位 | 6–8 次 | 27–32 次 | 31–39 ms → 28–35 ms |
| 两段间反复定位 | 7–8 次 | 26–28 次 | 38–41 ms → 30–49 ms |

同段定位调用由每轮 120 次降到 28–34 次；旧逻辑每轮有 116–117 次定位等待被取消，新逻辑只在松手时取消一次过时定位。收益主要是拖动过程中能持续呈现真实画面，跨段的最终延迟仍有波动。该对照使用浏览器、本地 HTTP 视频和独立控制器，不等同于 Electron 自定义媒体协议的耗时测量；无代理转码、云端 API 或安装包验证。

macOS Electron 复用已有开发服务，在独立示例项目实际拖动组合指针 10.7 → 5.0 → 11.18 → 1.78 秒，确认跨蓝／绿／橙片段后画面、时间和播放标记一致，松手保持暂停；连续播放也已检查。桌面验证期间刷新了现有窗口，没有重新启动开发服务。

## 桌面媒体协议与播放头同步

2026-09-30 进一步定位到 HTTP 回归页没有覆盖的桌面读取问题：`afflatus-media` 使用 `net.fetch(file://...)` 转发时，720p 原片和代理的 `duration` 正常，但 `seekable` 都是 `[0, 0]`。点击组合第 5 秒实际传入了原片第 25 秒，媒体却返回 `currentTime = 0`；原有定位函数只检查 `seeked` 和就绪状态，误判为成功。组合时间换算将入点之前的时间约束为 0，导致画面可以变化、时间读数与播放头却不走。

主进程现在使用独立的 `main/media/file-response.ts`，对受管素材和代理统一提供字节范围响应：`206`、准确的 `Content-Range`／`Content-Length`、`Accept-Ranges`、媒体类型，以及 `HEAD` 和无效范围处理。按范围流式读取，取消请求时关闭文件，缓冲按字节限制；继续使用项目和素材 ID 校验，不向渲染进程暴露文件路径。定位完成还会检查实际媒体时间，拒绝把跳回 0 的画面当成指定入点播放。

macOS Electron 在同一隔离项目“贵妃娘娘 · 720p 预览验证”实测：原片可定位范围恢复为 `0–88.979`／`0–57.469` 秒，代理也恢复完整范围；首段从原片 20 秒开始。点击刻度第 5 秒后，播放头为 5、原片时间为 25；拖动播放头跨段到第 15 秒，第二段原片时间为 10。连续播放越过第一段出点，组合播放头到 12.422 秒时第二段媒体时间为 7.422 秒，暂停状态一致。上述检查在实际桌面协议上完成，不以 HTTP 组件页代替。主进程修改后重载了开发服务；Windows、云端 API 和正式安装包未验证。

### 2026-09-30 轻量代理预览

进入编辑页后后台串行生成代理，最长边 540px（不放大小素材）、H.264、每 4 帧一个关键帧、无 B 帧、无音轨，保留源时间与帧节奏。FFprobe 核对源／代理起点和时长；不支持的时间戳、工具缺失、空间不足或转码失败均回退原片。单个输出上限 256 MiB，解码／编码各限制 2 个工作线程。首次准备期间显示轻量状态，完成后自动启用；不改写原片和裁剪参数。

拖动时原片不持续定位，两个代理缓冲复用片段；松手立即定位原片，停止移动 150 ms 也会恢复原片。高清帧完成前保留已显示画面，新输入使迟到的恢复失效；重新开始拖动不能先显示缓存里过时的代理帧。正常播放只使用原片音视频。最多四个视频元素，代理按需加载，退出编辑页释放全部解码器。这里提高的是定位与画面响应，不是 CSS 模糊或动画速度。

本机使用用户提供的两段 720×1280、30 fps H.264 素材验证。57.47 秒原片 12.03 MB，生成代理 8.50 MB，首次约 1.78 秒；88.97 秒原片 18.58 MB，生成代理 13.47 MB，首次约 2.69 秒。代理均为 304×540，复用缓存查询约 0–1 ms。密集关键帧服务于随机定位，不保证所有代理文件都比原片小。

浏览器通过本地 HTTP 读取真实文件，调用生产播放器和定位函数。每轮约 8 ms 间隔发送 180 个目标，实际持续 1.60–1.82 秒；原片／代理顺序交替，各三轮。用 `requestVideoFrameCallback` 的媒体时间和可见层切换记录实际新画面，单独统计拖动阶段，不把指针移动当作视频呈现。最终实现回归结果如下；原片基线已包含上一轮的请求合并与播放器复用优化。

### 2026-09-30 轨道空白与播放头拖动修复

旧实现把每段入点之和作为轨道的绝对偏移。验证组合的入点为 5 秒和 20 秒，实际总长 20 秒，却在轨道前留下 25 秒可滚动空白；初始滚动还依赖 ResizeObserver 中一次性的赋值。浏览器组件复现：1280px 视口的 scrollWidth 为 2800px，滚回最左后首段位于 x=1552px，整个窗口没有片段。旧播放头为 `pointer-events: none` 装饰，未提供独立抓取区域。

现在由 `use-timeline-viewport.ts` 管理会话相对原点、缩放锚点、裁剪期间的宽度保留和滚动约束；`timeline-layout.ts` 计算有效范围。已保存的入点不计入初始空白，恢复更早的内容时调整坐标基准和滚动位置。尺子裁切在自身范围内，末尾标签不再撑大滚动区域；宽度小于视口时仍延续秒数。播放头有 24px 的抓取区域，指针捕获保留鼠标与标记中心的偏移，反复拖动、松手与失焦释放复用同一定位逻辑。连续播放时使播放头保持可见。时间轴组件在开发热更新时整体重置手势和视口，避免钩子结构变化遗留旧坐标。

浏览器使用真实轨道组件、相同的 5–15 / 20–30 秒范围验证：638px 视口的初始 scrollWidth=638px、scrollLeft=0；连续往返拖动播放头 7 次成功，50% 缩放点击片段末尾之外仍定位至 20 秒；300% 滚动到最右 scrollLeft=1148px，最后一段右边缘保持在可视区域内。第二段入点向右拖动 50px 后，左边缘前进约 50px、右边缘误差小于 0.02px。新增范围单测覆盖缩放、空白约束、裁剪冻结与释放。本轮组件验证不包含云端 API 或正式安装包。

### 2026-09-30 裁剪入点与播放时间同步

另外复现了独立的播放边界问题：第一次加载尚未完成时，控制器的时间仍为 0；此时点击播放会把它作为源视频时间覆盖入点，确实可能播放已裁掉的开头。组合时间又使用 `max(0, 源时间 - 入点)`，因此画面在播放而播放头停在 0 秒。回归测试在修复前得到原片时间 0（预期 20），修复后从 20 开始，时间事件继续推进到 21，暂停状态与视频一致。

自适应播放器在开始播放前将目标限制到当前保留区间，底层播放器对直接播放及继续播放再次校验。暂停的裁剪预览仍可展示新扩展的边界，避免 React 草稿范围更新前阻止用户向外拉回素材。

浏览器用生产播放器和用户提供的两段 720p 视频连续验证：先播放 20–30 秒，再播放 5–15 秒，组合共 20 秒；101 个播放样本均在保留区间内（出点检查允许一帧以内调度误差），最终播放头为 20、视频暂停。实际拖动播放头从组合结尾回到 4.901315 秒，原片恢复到 24.901315 秒，代理隐藏且没有残留目标。macOS Electron 已观察到组合时间与播放头同步推进至 10.356 秒、当前片段切到第二段；桌面自动化仍存在窗口状态更新延迟，因此不将这一观察等同于完整桌面拖动验收。临时测试页面、视频副本和诊断代码已移出仓库；开发服务保持运行。未进行云端 API、Windows 或安装包验证。
