# 镜头草稿恢复

更新时间：2026-10-05。

镜头子画布在普通项目自动保存之外，另向固定应用数据目录 `workspace-drafts/` 保存恢复快照。项目盘暂时离线、项目数据库被替换或普通保存失败时，已确认写入的恢复快照仍保留。它不依赖项目目录或 `app.sqlite`，也不等待项目写入队列释放。

## 当前范围

- 覆盖 `GenerationWorkspace`：镜头及素材节点身份、文字和文本文件内容覆盖、位置、分组、视频／图片生成参数、标签、素材引用与镜头视口。
- 未失焦且尚未提交的名称输入、主画布卡片操作、裁剪、原始媒体和跨重启撤销记录不在本批范围。已提交进工作区的名称随快照保留。
- 拖动和长按等手势的确认方式不变；未完成的手势不作为已完成编辑恢复。
- 不承诺零丢失。渲染进程产生输入到主进程完成恢复写入之间仍有窗口；文件系统不可写、空间不足或进程提前终止时，尚未确认的输入可能丢失。界面会提示恢复副本未更新，普通项目保存继续尝试。

## 保存与恢复

恢复快照随编辑立即排队，串行写入并合并尚未开始的旧快照，不使用会被连续输入无限延后的尾部防抖。项目保存保留原有 350 ms 停顿触发，并增加 1 秒的检查间隔。项目提交前尽量等待对应快照保护完成；等待只针对调用时的序号，不等待持续输入产生的后续快照。

打开项目后，“镜头恢复草稿”提示显示保留的记录。应用不会自动把它写回项目：

- 项目工作区与草稿对应的完整确认版本一致时，点击“恢复镜头草稿”才写入；实际数据库事务再次核对完整内容与版本，防止检查后文件被替换。
- 如果内容已经提交、只是上次回执丢失，只有完整内容和预期下一版本号同时一致才认定已保存。点击“确认已保存”后清理恢复记录，不重复提交。
- 保存 A 期间继续输入 B，快照会同时保存确认基线、完整在途提交 A 和当前 B。重启后磁盘精确等于 A 时，可在 A 的基线上恢复 B；恢复 B 前先更新恢复记录，保证恢复过程再次中断也可重新识别。
- 项目内容与草稿对应版本不同，或原项目当前不可用时，不强行调整版本号、不覆盖、不自动合并。恢复副本继续保留，可以导出救援文件。
- 当前窗口有未保存编辑或恢复正在执行时，不能用旧恢复记录替换当前编辑。恢复成功不重建跨重启撤销历史。

恢复期间显示明确进度，暂时禁用镜头进入、新建、画布编辑和子画布返回，较早取得的入口回调也不能绕过恢复状态。恢复完成后保留仍存在的当前镜头，已被恢复内容移除的镜头才退回主画布；返回首页和原生关闭继续等待同一个恢复任务。数据库已经提交不代表界面已接收结果，入口会在界面完成恢复后重新启用。

当前会话在项目失联或恢复保护报错时，也有“导出当前镜头草稿”入口。导出不要求先把草稿写回原项目；即使内部恢复目录不可用，仍可选择其他目录保存。

## 文件格式与清理边界

内部记录格式为 `infinite-afflatus-workspace-draft`，版本 `1`。每条记录含项目 ID／目录身份、会话 ID、单调递增 `seq`、时间、完整 `baseline` 和 `workspace`；可选 `lastSubmitted` 保存预期下一版本的完整在途提交。没有该可选字段的版本 1 记录继续按完整基线比较，不猜测中间提交。工作区本身沿用现有格式，未修改历史项目字段。

写入先创建独占临时文件，完成文件同步后原子替换目标，并同步目录。单条记录上限 16 MB，恢复目录总量上限 256 MB，文件数量上限 2048；替换按最终总量计算。超限、目录被替换、符号链接或记录损坏会报错并保留旧内容，不能静默从空记录重新开始。

确认项目已保存后删除精确序号的记录；进程内保留已确认序号水位，防止迟到请求复活旧记录。旧进程的 IPC 不会跨重启到达，因此不永久保留完整已保存快照。删除前复核读取时的文件身份；改变过的文件不清理。损坏记录单独报告，不阻止原项目继续使用。

导出文件扩展名是 `.afflatus-draft.json`，格式为 `infinite-afflatus-workspace-rescue`、版本 `1`。它是可阅读的只读救援文件，包含草稿及确认版本，不含原始媒体，**不能通过项目包导入入口作为完整项目打开**。导出只创建新文件，不覆盖已有文件，也不删除内部恢复记录。

## 验证

- `tests/workspace-draft.test.ts`：独立存储重开、损坏应用库、序号交错、正常保存清理、原子写失败、符号链接与损坏记录保留、配额、丢失回执、A／B 连续恢复、事务内同版本替换、外部救援导出和删除身份竞态。
- `tests/workspace-draft-queue.test.ts`：慢写下持续输入的固定序号等待、保护失败仍保留最新内容、重试和旧回执隔离。
- `tests/browser/save-lifecycle.cjs`：使用独立恢复记录的模拟接口，验证正常返回前排空项目保存与恢复清理、失败留页、原生关闭和超时重试。
- `tests/browser/draft-recovery.mjs`：隔离生产 Electron／IPC／SQLite，项目离线期间输入后强杀进程，重启遇到同 ID／同 revision 的变化数据库时保留冲突，再放回原库并显式恢复文字。
- `tests/browser/draft-recovery-controls.cjs`：真实 React／React Flow 配合延迟的模拟接口，核对数据库提交、IPC 回复与界面刷新三个时点之间的操作保护；现有镜头保持、返回首页和原生关闭等待、恢复失败留页。不把模拟接口用例计为真实存储或云端验证。
- `tests/upgrade/workspace-draft-preservation.test.ts`：固定提交 `29f19980b993a4462d3c97605ea55be51806a037` 为恢复格式 v1 的历史写入基线。独立进程仅加载该提交的 Git 归档业务代码，分别创建普通未提交草稿和 A 已提交、B 带 `lastSubmitted` 的记录；当前版本恢复后，再用两个独立进程核对完整内容、参数、分组与素材引用、原媒体哈希及确认清理边界。既有存储与项目包基线不变，随 `pnpm test:upgrade` 执行，详见[版本升级数据回归](data-upgrade-testing.md)。

这些验证属于本地代码和桌面恢复链路。它们不代表云端生成 API、Windows 安装环境或签名安装包验证。

项目名称输入与已完成裁剪使用另一种独立恢复格式，见 [项目名称与裁剪恢复](project-edit-recovery.md)。本页的镜头工作区文件和救援格式不因此增加名称或裁剪字段。
