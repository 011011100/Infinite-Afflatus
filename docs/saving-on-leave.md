# 离开页面与关闭应用前保存

更新时间：2026-10-04。

返回项目首页、关闭窗口和退出应用会先等待当前编辑内容落盘；保存失败时保留页面与草稿，提供重试，不自动丢弃修改。设置中的目录迁移操作同样先提交草稿。

渲染进程由 `features/lifecycle` 汇总各编辑器的保存操作：先完成素材导入并添加引用，再等待裁剪队列，随后保存镜头草稿、主画布操作和最新视口。每个编辑器仍负责自己的内容和错误，保存协调器不复制一份项目数据。视口串行保存；写入期间继续移动时，完成旧写入后再提交最新位置，失败保留最新位置供重试。

裁剪失败时预览恢复最后保存的范围，待保存的手势仍保留在队列内。「重试保存」会重新提交；如果用户直接开始新的裁剪手势，则以新的编辑意图替代失败队列。正在进行、尚未松手的裁剪手势会阻止退出，需要先完成或取消该手势。

主进程关闭窗口或退出时发送带随机标识的保存请求；只接受当前受信窗口主 frame 对同一请求的布尔回执。成功后才销毁窗口，或继续关闭后台存储。保存中禁用页面编辑；失败或超时保留窗口，过时回执不能授权后来的一次关闭。超时不代表已保存，应用不强制退出。

验证：

- `tests/save-lifecycle.test.ts` 覆盖导入与草稿的保存顺序、失败后重试、视口写入串行与保留、错误窗口／过时回执拒绝及超时。
- `tests/trim-save-queue.test.ts` 覆盖等待全部裁剪操作和保留失败手势后重试。
- `pnpm exec electron tests/browser/save-lifecycle.cjs` 复用现有开发服务与合成草稿，检查防抖前返回、失败留页恢复及退出确认后冻结。该测试使用模拟桌面接口；真实 IPC／SQLite 关闭重开另由桌面交付回归验证。

该机制保护正常返回、关闭与退出，不承诺在操作系统强杀进程或断电时保存尚未提交到主进程的内存草稿。
