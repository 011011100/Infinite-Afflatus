# 导入恢复文件

设置 → 保存与存储 → 恢复文件支持重新读入此前导出的 `.afflatus-draft.json` 和 `.afflatus-edit-draft.json`。它们分别保护整个镜头工作区，以及一次名称输入或一张组合卡片的裁剪。文件不含原媒体，不是完整项目包，不能用来新建一个空项目后继续编辑。

## 操作顺序

1. 点击「导入恢复文件」，在原生文件选择器中选取文件。取消不会新增副本。
2. 检查预览中的原项目、保存时间、类型、影响范围和当前版本匹配情况。名称保留原始输入，包括空白；镜头文件影响整个镜头工作区，不只是一条镜头。
3. 点击「导入为恢复副本」后，只向独立恢复目录添加副本。原项目、当前编辑输入、原救援文件和既有恢复副本保持。
4. 当前项目的恢复提示更新；其他项目需要用户稍后打开。导入不会切换项目、自动保存当前输入或直接应用恢复内容。
5. 继续使用已有恢复操作：名称填回原改名弹窗，再明确保存；裁剪点击「恢复并保存裁剪」；镜头工作区通过完整版本核对后恢复。当前编辑和恢复锁继续生效，冲突不能强制覆盖。

完整项目迁移或跨设备复制仍使用 `.afflatus` 项目包。由项目包创建的副本有新的项目 ID，不能仅因同名而接收原项目的恢复文件。

## 文件与保存边界

- 外层只接受两种已发布的 v1 救援格式，再由既有验证器核对内部草稿。扩展名和说明文字不能作为内容有效的凭据。
- 原始 JSON 读取上限为 64 MiB，允许既有导出器的缩进空白；独立草稿仍遵守 16 MiB 单文件及原有目录配额。不支持的版本、损坏文件、符号链接和读取中被替换的文件明确拒绝，保留源文件。
- 预览凭据绑定原生窗口、源文件身份与内容，以及当前原项目的位置和内容。确认前重新核对；文件或项目变化时重新检查，不使用旧预览继续导入。
- 项目 ID 和目录标识必须精确对应当前项目。找不到原项目时不按名称重绑、不创建空项目；引用素材必须已经登记在原项目中并可安全读取，不能借导入认领暂存文件。
- 旧镜头文件只包含素材引用 ID，没有当时原媒体的完整哈希证明。导入检查当前已登记素材的可访问性，不声称救援文件能找回缺失媒体或证明过去的媒体字节。
- 新副本使用独立恢复流和从 1 开始的顺序，保留原始基线、目标、在途提交、素材元数据和原保存时间。外部文件的旧会话顺序及已保存标记不能覆盖活动草稿或跳过恢复核对。
- 同一确认重试或重复选择相同内容时复用尚存的相同导入副本，不覆盖其他内容。副本写入持久化后才返回成功；导入不执行保存队列、迁移、媒体移动或旧文件清理。

## 验证范围

原生集成测试核对源文件变化、窗口凭据、并发确认、重复导入、写入失败、原项目与活动草稿保留。界面回归分别验证选择取消、预览与确认分离、迟到回执、切换设置页以及列表刷新。历史兼容验证使用固定旧提交的真实公开导出器生成文件，再由当前版本导入和明确恢复，并在两个独立进程重开核对。

这些检查分别证明格式兼容、保存边界和桌面交互；不代表云端 API、正式签名安装器或断电零丢失。实际通过记录统一记在 [商业可用性推进](commercial-readiness.md)。
