# 应用索引与设置备份

应用索引与设置备份用于本机 `app.sqlite` 损坏或缺失后的恢复。入口放在「设置 → 保存与存储」，不增加主画布按钮，也不改变项目、镜头和裁剪的保存入口。

## 与项目包的区别

此备份保存应用数据库的一致快照，包括项目目录记录、快捷键等应用设置和历史任务记录。它不复制项目 SQLite、原媒体、暂存结果或独立恢复草稿。完整项目的转移和异地备份继续使用 `.afflatus` 项目包。

本机备份保存在应用数据位置的 `app-backups`，不能代替对整块磁盘的备份。项目媒体、暂存文件及两类独立草稿在恢复时原地保留，不因为恢复应用索引而回退项目内容。

## 创建和检查

打开保存设置后读取备份列表；打开其他设置页不会扫描备份。点击「创建本机备份」生成一份新的快照，不覆盖旧备份。完成后显示时间、原项目目录、项目数、历史任务数、大小和创建版本，并可打开固定的备份位置。列表刷新失败与备份创建失败分别提示，已经成功创建的备份不会因随后刷新失败而变成“未保存”。

快照使用 SQLite 的一致备份机制，不能直接复制仍在使用的主数据库文件。快照与清单校验完成后才发布，清单绑定当前应用资料目录、项目根目录身份和恢复代际。关闭应用会等待已开始的快照操作结束。已有备份、损坏文件或未知版本不会被自动覆盖或删除。

项目目录迁移会使此前的恢复代际失效。仅路径名称相同不能证明旧目录仍然有效；曾迁往另一块磁盘后保留的旧副本不能被恢复成当前项目目录。迁移未稳定、标记损坏或目录身份变化时，备份保留但不能用于恢复。

独立恢复标记与应用库中的代际令牌必须一致。迁移切换和备份恢复都会更新代际；放回这些操作之前的旧代际数据库，会在启动工作任务前被拒绝。迁移切换确认中断时保留两边资料并暂停写入，界面要求关闭重开；重开只按独立切换记录核对目标内容并继续，不猜测回退方向。这个标记不记录每一次项目编辑，不能把它理解为任意文件替换的全历史检测。

## 启动失败后的恢复

原有「重试」「查看位置」「退出」继续保留，新增「检查本机备份」。先检查最近备份，也可通过原生选择器选取当前应用备份目录中的另一份备份。

检查通过后，确认页显示备份时间、原项目目录、当前项目数量，以及待保留的任务和文件数量。取消是默认动作；只有明确确认，才使用该次检查产生的有效凭据执行恢复。检查后资料发生变化或凭据失效，需要重新检查。

恢复发生在项目库和业务 IPC 启动之前。当前应用数据库及 journal／WAL／SHM 文件先原样保留到 `app-backup-retained`；数据库之外另存恢复进度。过程中断时，后续启动按这份进度核对实际文件，不能因 `app.sqlite` 暂时缺失而初始化空库。

新的工作库只采用受支持的应用设置，并从当前项目数据库重建索引。原项目名称、画布、工作区、媒体和已完成裁剪不回退。旧迁移、文件清理、导出及保存任务记录另存保留，不作为新一次执行或删除的授权；再次启动也不能重放。设置页显示恢复记录、保留任务／文件数及保留资料位置。

如果当前项目或恢复草稿仍依赖无法从项目素材中核实的暂存引用，拒绝此次自动恢复。历史队列接管、孤立文件认领、任意项目盘重新定位和整个应用资料打包尚不在此入口范围。保留文件不等于已经恢复为可继续执行的任务。

## 验证边界

验证应分别覆盖：真实在线 SQLite 快照；备份损坏、目录替换、迁移代际和确认失效；恢复替换中断后的原库与旁路文件保留；历史保存及清理授权隔离后两个独立进程重开；真实设置操作和生产启动恢复。固定历史提交必须由旧代码写入，不得用当前实现伪造旧记录或更换原有升级期望。

同类产品中，配置备份入口与导入前检查可参考 [VS Code Profiles](https://code.visualstudio.com/docs/configure/profiles#_share-profiles)，按时间辨认恢复资料及保留退出机会可参考 [Audacity 恢复流程](https://manual.audacityteam.org/man/recovery.html)。本项目仍使用自己的设置、原生启动故障入口和独立项目保存逻辑。
