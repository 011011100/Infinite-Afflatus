# 商业可用性推进清单

更新时间：2026-10-05。用户授权持续完善，沿用现有主画布／镜头子画布交互。此清单记录验收差距，不代表已正式发布。

## 当前推进原则

先保证一次完整本地创作能够保存、导出、备份、恢复，再扩大生成与交付范围。账号、计费、ComfyUI、多轨剪辑和协作不自动加入本批；中间切开、重排和画面裁切仍遵守现有暂不实现的约定。云端模型、凭证、费用与正式平台范围需要有明确依据，不能用模拟结果宣称完成。

## 第一批：交付与数据保护

| 能力 | 当前实现 | 尚需验证／完善 |
| --- | --- | --- |
| 退出前保存 | 返回首页、窗口关闭和退出等待草稿；失败留页重试 | 未提交名称和主画布裁剪的崩溃恢复；真实用户桌面长时间验证 |

## 第二批：编辑容错与素材恢复

镜头素材画布已有独立会话撤销／重做，连续文本与参数输入合并，平移缩放不入栈。项目首页已支持名称搜索与排序。`.afflatus` 首版导出器已固定到 `8b70add2f30f1df960bcc70e0afdd1fb91609109`，旧代码生成项目包、当前代码导入并跨进程重启验证。

素材检查支持打开项目时检查位置、按需完整校验和精确恢复缺失原文件。恢复只接受原内容，不覆盖已有文件或改写项目数据库，恢复后刷新媒体显示而保留画布草稿。详见 [素材恢复边界](media-recovery.md)。

## 第三批：项目故障期间的草稿保护

已打开项目读取或保存失败后，保留当前编辑器、未保存输入和撤销记录，暂停写入；全局保存队列和目录状态继续刷新。放回原项目文件后，显式重试先核对各编辑器最后确认的内容，旧备份或冲突不会自动变成新保存基线。名称输入、镜头草稿和裁剪的离开检查共用保存流程。

已有项目写入核对索引身份、表结构与完整性，并使用 SQLite `mode=rw` 禁止误建空库；目录迁移在切换前再次核对目标副本身份。实际 macOS 桌面已验证移走／放回 SQLite、阻止未保存关闭、保留同一输入框和拒绝同 ID 旧备份；Windows 桌面与正式安装包仍待验证。保留仅限当前窗口，不代表已实现崩溃后的草稿恢复。详见 [项目管理](project-management.md)。

## 第四批：导出准备、组件检查与内部打包

返回首页、关闭窗口和退出前会取消尚在准备的导出，包括等待目录写入、复制与大文件校验，并等待清理释放写入通道后保存草稿；已进入编码／合成的任务在 macOS 仅关闭窗口时继续。较早打开的文件选择器不能在取消后重新启动导出。

设置新增「视频处理」，主动检查 FFmpeg／FFprobe 的可执行位置、版本和失败原因；导出、代理预览和诊断共用路径解析。macOS 支持 Finder 环境下的常见安装位置，检查有时间和输出上限。详见 [媒体工具](media-tools.md)。

已有锁定工具链、仅收集运行文件的内部打包、ASAR 内容核查，以及手动 Windows／macOS 打包工作流。本机 macOS ARM64 未签名 ZIP 已构建成功，并用实际包内程序和独立临时项目完成设置诊断、文字保存、关闭后重启读取验证；渲染器隔离与生产 CSP 检查通过。全量测试 254 项中 251 项通过、3 项真实媒体用例按默认配置跳过；真实媒体另行执行通过。历史数据升级仍使用原有固定基线。

上述包内启动不等于安装、覆盖升级、卸载保留数据或正式签名验证。FFmpeg 尚未内置，云端 API 尚未实测。详见 [桌面内部包与分发边界](desktop-distribution.md)。

Windows／macOS 的内部包 CI 已在提交 `9ccde342582c693cf0da35719e04d730bf773d72` 通过，两端均运行了实际包内程序并验证保存与重启读取。Windows 安装程序已生成，安装器执行与安装升级仍待验证。

## 第五批：启动重连与镜头崩溃恢复

启动时原保存盘离线或应用数据库无法安全打开，会保留恢复入口，允许查看原位置、重试或退出。已有空库、损坏库、较新版本、缺失表／根目录和文件替换不会触发重建空库；只有确认没有受管数据痕迹时才初始化新库。macOS 真实生产入口已验证三类启动故障，原项目、应用数据库和暂存结果保持，原路径恢复后重试可继续。详见 [启动恢复](startup-recovery.md)。

镜头工作区另存独立于项目盘和应用数据库的恢复快照，保护文字、参数、分组、素材引用及布局。连续输入不会无限推迟保护；项目写入与新输入交错时记录已提交内容，防止旧回执清理新草稿。重新打开后由用户选择恢复，写入事务再次核对完整原内容；冲突保留副本并支持导出只读救援文件。确认保存后清理对应副本，未确认内容不自动删除。

macOS 生产应用已完成实际强杀回归：移走项目数据库仍可保护输入；强制结束进程后，同 ID、同 revision 的不同内容被识别为冲突且文件不变；放回原库后显式恢复并显示文字。全量测试 298 项中 295 项通过、3 项真实媒体用例按默认配置跳过，固定历史升级测试通过。此处不承诺硬件断电零丢失，也不包含尚未提交的名称输入、主画布裁剪或跨重启撤销历史；应用数据库损坏时仍须先恢复原库才能进入项目恢复界面。

## 第六批：恢复交互与 Windows 安装验证

恢复期间冻结镜头进入、新建和画布编辑，返回首页／原生关闭等待完整恢复；恢复后保留仍存在的当前镜头，不再被迟到回执关闭。五条真实 React／React Flow 延迟接口用例通过，另有真实生产 Electron 强杀恢复证明。恢复格式 v1 已固定历史写入提交，升级回归增至 21 项，原有基线保持不变。

提交 `1ee25bcbceea9047ee464b3d1f5d7202d4485b77` 的 [Windows／macOS 内部包回归](https://github.com/011011100/Infinite-Afflatus/actions/runs/37218359821) 已通过。Windows 在临时 CI 机器实际安装、同版本覆盖、重开并卸载，核对默认资料目录、项目和恢复草稿保留；两端启动故障与强杀恢复也通过。这仍不是正式签名安装包或历史安装版升级验收。

## 第七批：参考素材部分导入失败

参考素材接收失败不再向镜头加入失效引用。一批文件中的成功项仍可编辑与保存，失败项显示数量和逐文件原因；完整暂存引用与失败部分文件的保护边界不变。新增五项存储回归，本机真实 Electron 验证有效文本／空文件／有效文本的混合选择，以及随后编辑、保存、返回首页重开和原文件不变。当前全量测试 303 项中 300 项通过、3 项真实媒体用例按默认配置跳过，升级 21 项通过。

提交 `3c4cdfe0692e50ed5110f0bab0ac529ebdcc5a8c` 的标准检查、三个系统的历史升级与 [两端桌面回归](https://github.com/011011100/Infinite-Afflatus/actions/runs/37218726447) 全部通过。该次 Windows／macOS 均实际执行部分参考素材导入与后续编辑／重开；Windows 安装、同版本覆盖与卸载保留数据再次通过。云端 API、正式签名与历史安装版升级仍未验证。

## 继续推进

1. 应用数据库备份恢复入口、保存盘改名后的安全重定位；不可用项目不能变成空项目。
2. 未提交名称与主画布裁剪的崩溃恢复、救援文件导入和完整独立项目恢复。
3. 大项目性能、长时间操作、键盘可访问性与更多真实媒体验证，持续保持低常驻按钮密度。
4. 正式桌面交付：决定平台范围，完善媒体工具分发与第三方许可，补充 macOS 安装与历史版本覆盖升级；签名和渠道需真实发布配置。
5. 云端生成：按确认的服务商与凭证接入上传、提交、轮询、取消、失败重试和候选采用，真实调用验证后才宣布可用。任务结果继续经过独立暂存与保存队列。

“商业可用”至少需要核心创作闭环、数据保护、故障反馈、历史兼容、目标平台安装体验与性能验证共同达标。静态构建通过只证明工程可构建，不能替代后面几项。
