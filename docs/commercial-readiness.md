# 商业可用性推进清单

更新时间：2026-10-05。用户授权持续完善，沿用现有主画布／镜头子画布交互。此清单记录验收差距，不代表已正式发布。

## 当前推进原则

先保证一次完整本地创作能够保存、导出、备份、恢复，再扩大生成与交付范围。账号、计费、ComfyUI、多轨剪辑和协作不自动加入本批；中间切开、重排和画面裁切仍遵守现有暂不实现的约定。云端模型、凭证、费用与正式平台范围需要有明确依据，不能用模拟结果宣称完成。

## 第一批：交付与数据保护

| 能力 | 当前实现 | 尚需验证／完善 |
| --- | --- | --- |
| 退出前保存 | 返回首页、窗口关闭和退出等待草稿；失败留页重试 | Windows 真实桌面；进程崩溃后的未提交文字恢复 |
| 成片导出 | 已保存组合／裁剪输出 MP4、任务进度、取消、失败重试 | 大项目压力、更多真实编码、HDR、安装包内置工具 |
| 项目备份 | 项目包、创建副本、导入独立项目、安全校验 | 大体积百分比进度、跨系统桌面往返、定时备份 |
| 升级保护 | 固定历史提交生成数据并跨进程核对 | 安装器覆盖升级与正式数据格式发布基线 |

## 第二批：编辑容错与素材恢复

镜头素材画布已有独立会话撤销／重做，连续文本与参数输入合并，平移缩放不入栈。项目首页已支持名称搜索与排序。`.afflatus` 首版导出器已固定到 `8b70add2f30f1df960bcc70e0afdd1fb91609109`，旧代码生成项目包、当前代码导入并跨进程重启验证。

素材检查支持打开项目时检查位置、按需完整校验和精确恢复缺失原文件。恢复只接受原内容，不覆盖已有文件或改写项目数据库，恢复后刷新媒体显示而保留画布草稿。详见 [素材恢复边界](media-recovery.md)。

## 第三批：项目故障期间的草稿保护

已打开项目读取或保存失败后，保留当前编辑器、未保存输入和撤销记录，暂停写入；全局保存队列和目录状态继续刷新。放回原项目文件后，显式重试先核对各编辑器最后确认的内容，旧备份或冲突不会自动变成新保存基线。名称输入、镜头草稿和裁剪的离开检查共用保存流程。

已有项目写入核对索引身份、表结构与完整性，并使用 SQLite `mode=rw` 禁止误建空库；目录迁移在切换前再次核对目标副本身份。实际 macOS 桌面已验证移走／放回 SQLite、阻止未保存关闭、保留同一输入框和拒绝同 ID 旧备份；Windows 桌面与正式安装包仍待验证。保留仅限当前窗口，不代表已实现崩溃后的草稿恢复。详见 [项目管理](project-management.md)。

## 第四批：导出准备、组件检查与内部打包

返回首页、关闭窗口和退出前会取消尚在准备的导出，包括等待目录写入、复制与大文件校验，并等待清理释放写入通道后保存草稿；已进入编码／合成的任务在 macOS 仅关闭窗口时继续。较早打开的文件选择器不能在取消后重新启动导出。

设置新增「视频处理」，主动检查 FFmpeg／FFprobe 的可执行位置、版本和失败原因；导出、代理预览和诊断共用路径解析。macOS 支持 Finder 环境下的常见安装位置，检查有时间和输出上限。详见 [媒体工具](media-tools.md)。

已有锁定工具链、仅收集运行文件的内部打包、ASAR 内容核查，以及手动 Windows／macOS 打包工作流。本机 macOS ARM64 未签名 ZIP 已构建成功，并用实际包内程序和独立临时项目完成设置诊断、文字保存、关闭后重启读取验证；渲染器隔离与生产 CSP 检查通过。全量测试 254 项中 251 项通过、3 项真实媒体用例按默认配置跳过；真实媒体另行执行通过。历史数据升级仍使用原有固定基线。

上述包内启动不等于安装、覆盖升级、卸载保留数据或正式签名验证。FFmpeg 尚未内置，云端 API 尚未实测。详见 [桌面内部包与分发边界](desktop-distribution.md)。

## 继续推进

1. 应用启动时原保存盘离线的重连入口、数据库损坏后的独立恢复；不可用项目不能变成空项目。
2. 崩溃后草稿恢复与冲突草稿另存。
3. 大项目性能、长时间操作、键盘可访问性与更多真实媒体验证，持续保持低常驻按钮密度。
4. 正式桌面交付：决定平台范围，完善媒体工具分发与第三方许可，验证安装与覆盖升级；签名和渠道需真实发布配置。
5. 云端生成：按确认的服务商与凭证接入上传、提交、轮询、取消、失败重试和候选采用，真实调用验证后才宣布可用。任务结果继续经过独立暂存与保存队列。

“商业可用”至少需要核心创作闭环、数据保护、故障反馈、历史兼容、目标平台安装体验与性能验证共同达标。静态构建通过只证明工程可构建，不能替代后面几项。
