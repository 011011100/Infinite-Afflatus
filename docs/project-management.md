# 本地项目管理

更新时间：2026-09-28。本文包含整体设计。项目创建、SQLite 持久化、统一目录迁移、暂存和保存队列已实现第一版；项目包导入导出等尚待实现。实际边界见 [存储实现与验证](storage-implementation.md)。

## 已确定与建议

已确定：本地数据库使用 SQLite；设置中统一配置一个项目保存目录，新建项目不再逐个选择位置；修改保存目录需要迁移已有项目。已有生成任务在切换后保存到新目录，迁移成功后自动清理原位置的项目重复数据，保留用户另放的文件。项目独立保存，方便项目导入导出。

已落实一个项目一个文件夹、每项目独立数据库、素材复制进项目目录、视口保存和轻量项目首页。当前使用 Node 内置 SQLite，表结构先覆盖项目与素材；完整镜头编辑关系、格式升级和项目包扩展名后续确定。

## 项目与应用分开保存

| 存储 | 建议位置 | 内容 |
| --- | --- | --- |
| 项目数据库 | 统一保存目录下自动创建的项目子目录内 | 名称、镜头、分镜文本、参考图关系、素材索引、生成记录、组合顺序、裁剪参数、画布布局与视口 |
| 项目素材 | 同一项目的 `assets/` | 导入和生成的视频、图片原件及保留的候选版本 |
| 项目缓存 | 同一项目的 `cache/` | 可重新生成的缩略图、代理视频和预览缓存 |
| 结果暂存区 | 固定的 `userData/staging/`，在项目保存目录之外 | 尚未正式保存的生成结果及下载中的文件，不能按普通缓存淘汰 |
| 应用数据库 | Electron 的 `userData` 目录 | 统一项目保存目录、偏好设置、项目位置索引、迁移日志与持久化保存队列 |

应用数据库不是项目内容的唯一副本。即使清空最近项目列表或重装软件，只要项目目录仍在，就可以重新打开；卸载流程不应删除用户项目。服务商密钥由后续凭证方案单独处理，不写入可分享的项目数据库或项目包。

建议目录：

```text
统一项目保存目录/
  雨夜归途/
    project.sqlite
    assets/
      videos/
      images/
    cache/
  海边来信/
    project.sqlite
    assets/
    cache/
```

目录名仅为展示名称，项目有独立 ID。项目格式版本和数据库结构升级记录存在项目数据库内，不再维护另一份重复描述项目状态的 JSON。保存目录迁移记录由应用数据库管理。

统一保存目录建议初始为用户文档目录下的 `Infinite Afflatus`，用户只在设置中更改。新建、创建副本和导入项目包均使用此目录，不再弹出项目保存位置选择器。每个项目的子目录由软件自动创建，同名项目用唯一标识区分，不能覆盖已有目录。

修改保存目录时迁移原目录下的全部项目，成功后新旧项目统一使用新位置。设置不会先改路径再后台慢慢搬移。原保存目录未连接或不可读时，先提示恢复连接，不能把无法读取的项目当作不存在而完成迁移。

## 更换保存目录与迁移

设置页显示当前保存目录和「更改并迁移」入口。选择目标后展示项目数量、需复制的数据量、目标剩余空间，以及迁移期间暂停编辑、完成后自动清理旧项目数据的说明。用户点击「开始迁移」后展示进度、当前阶段和取消操作；复制、校验、切换和清理分别显示状态。

建议使用以下流程：

1. **检查范围与目标。** 扫描原保存目录里的全部项目，包括已从最近列表移除的项目；从项目和受管文件记录建立迁移清单，不把目录中的所有文件一律纳入。目标必须可写且空间足够；第一版使用空目标目录，不合并已有项目库，不覆盖文件。规范化路径并拒绝原目录自身、相互嵌套的目标以及与应用数据库／结果暂存区重叠的项目根目录。未识别文件留在原处并列明，不承诺已迁移。
2. **保存并暂停项目写入。** 先锁定项目库、阻止保存队列启动新的项目提交，提交待保存编辑，暂停新建、导入、复制及其他直接写项目的操作。等待已经开始的保存／媒体操作完成或安全结束，再关闭项目文件句柄和数据库连接，冻结迁移清单。保存失败则不启动复制，其他窗口／实例不能绕过锁。云端生成和向独立暂存区下载继续进行，文件与待保存任务可靠落盘；无需等所有生成任务结束才迁移。
3. **复制到目标临时区。** 复制清单中的项目数据库和素材，保留项目 ID 与内部相对路径。明确登记的可重建缓存可以跳过，开始前列入容量说明，并记录后续清理规则。跨盘也走复制流程，不依赖跨盘重命名，校验及切换前保留全部源数据。
4. **完整校验。** 根据迁移清单核对文件数量、大小和内容校验值，检查 SQLite 数据库可打开、完整性以及素材引用。全部项目通过后，目标才成为可用项目库；目标临时项目不进入正常打开列表。
5. **统一切换。** 先确保目标文件完整、可持久恢复，再用应用数据库事务一起更新保存根目录、相关项目索引、存储版本以及「已切换，待清理」状态。使所有旧路径写入失效，当前项目仍指向原来的项目 ID，后续读写只能使用新目录。
6. **清理与恢复。** 在恢复项目写入前完成首轮源数据清理，只删除满足下述规则的清单项；随后恢复编辑并唤醒保存队列，将暂存结果提交到新目录。清理失败项保留可重试记录，新目录仍然有效；不为了删除失败一直阻塞保存，也不自动回退到旧副本。最后显示已释放空间、保留的用户文件及待清理项。独立暂存区不在旧目录清理范围内。

整个迁移的状态记录留在应用数据库，至少包括迁移 ID、原路径、目标路径、迁移清单、逐文件复制／校验／删除结果、切换凭据和当前阶段。异常退出后先根据记录判断是否已经切换：未切换时保留原目录为有效位置，重新检查源文件后才允许重试；已切换时继续使用校验完成的新目录，恢复尚未处理的任务事件及清理。复制阶段源内容变化则重新生成清单；切换后的清理阶段源文件变化则保留该文件，不将它追加入删除清单。

取消在最终切换前生效，切换前取消或失败后恢复原目录及原索引，保留项目可用。此时只清理本次迁移创建的临时内容，不删除目标中不属于本次任务的文件。最终切换开始后不再回退到旧目录，清理阶段可以停止并稍后重试；不能出现部分项目已切换、另一部分仍依赖旧目录的成功状态。

旧项目重复数据默认自动清理，不默认长期留作备份。发生部分清理失败时显示「已切换，部分旧文件待清理」，提供重试；不能将它标为全部清理完成，也不因此回滚已生效的新目录。

迁移范围是统一保存目录下的软件项目。通过「打开项目」临时打开的外部项目不被擅自搬动，需要先通过项目包导入到项目库。应用数据库、偏好设置和结果暂存区仍保存在 `userData`，不跟随项目目录搬移。

### 生成与保存分开

已确定：保存结果时遇到迁移，要先缓存文件，迁移完成后再保存。建议所有生成结果统一下载到独立磁盘暂存区，再交给持久化保存队列；没有迁移时立即提交，有迁移时只等待项目写入，生成和下载无需感知搬移细节。详细规则见 [生成与保存](generation-saving.md)。

任务记录关联项目 ID、任务 ID、服务商任务 ID 和结果素材 ID。保存模块在实际提交时解析当前目录，不使用生成开始时的绝对路径。检查迁移状态与取得项目写入许可必须统一协调，迁移要等已开始的保存操作完成，不能只做一次无锁的状态判断。

每个项目 ID 只有一个明确的活动位置。发现手动复制的同 ID 项目时，不自动覆盖位置索引或改写在途任务的目标；先明确作为独立副本导入或恢复项目的意图，旧目录残留副本不能重新接管任务保存。

| 迁移发生时的任务状态 | 处理规则 |
| --- | --- |
| 云端仍在生成 | 保留服务商任务 ID，继续查询；完成后进入统一的下载、暂存、排队流程 |
| 已收到结果，尚未下载 | 持久化结果信息，下载到独立暂存区，不等待迁移结束 |
| 正在下载到暂存区 | 继续下载；完整校验后进入待保存队列，不向旧项目目录写文件 |
| 已暂存，尚未提交项目 | 迁移期间显示等待，切换成功后提交新目录；切换前取消或失败则提交原目录 |
| 正在提交项目文件和素材记录 | 已取得写入许可的操作先结束，迁移再复制项目；保留暂存文件直到提交被确认 |
| 切换后收到迟到回调、重试或应用重启恢复 | 按任务和结果 ID 去重，由保存模块重新查当前目录；禁止重新创建旧目录 |

缓存必须是完整落盘的文件，不能只保留内存或远端 URL。应用数据库中的保存队列记录暂存位置和提交状态，重启后先恢复迁移状态，再处理缓存结果。结果文件及项目素材记录提交成功、队列确认后，才清理对应暂存文件。项目中的 `cache/` 是可重建缓存，独立暂存区里的未保存结果是待交付数据，两者清理策略不同。

界面区分「生成中」「下载中」「已缓存，等待迁移」「保存中」「已保存」。云端成功或缓存完成都不能显示为已保存到项目。失败重试优先复用缓存结果，不重新付费生成；下载失败、缓存空间不足和结果链接过期规则见 [生成与保存](generation-saving.md)。

### 旧数据只按受管文件清单清理

软件在创建项目数据库、导入／生成素材、建立缓存和临时下载时登记文件归属。清理清单包含项目 ID、受管文件 ID、相对路径、文件类型、源文件身份与内容校验值、目标校验结果及清理状态。遍历目录只能用于发现和核对，不能把所有发现的文件自动登记为软件所有。

- **已复制的项目数据：** 只有目标已经完整校验并成功切换，且源文件身份、内容仍符合冻结清单时才删除。删除前再次确认目标项目可用、源位置仍属于本次迁移，不能仅比较文件名或后缀。
- **缓存和下载临时文件：** 仅清理有受管登记且明确可重新生成／重新下载的文件，活动任务所需数据先保留或完成转移；这些不依赖目标存在同名副本。未确认下载结果可恢复前，不删除未完成的唯一副本。
- **用户另放的文件：** 无论在项目旁、项目里面还是 `assets/`／`cache/` 内，只要未登记归属就保留；不因扩展名相同而删除。迁移后用户新放入、修改或替换的文件也不得删除。
- **目录与链接：** 不跟随符号链接、目录联接或其他重定向向外清理；发现路径或祖先目录身份改变就跳过并提示。只对已登记、检查为空的项目子目录执行空目录删除，失败就保留；绝不递归删除用户选择的原根目录。

源文件清理与项目写入受同一后台调度管理，源文件操作针对已核验的位置，不允许旧任务重新打开它。首次清理在目标项目重新开始写入前执行。后续重试要核验持久化的复制／切换凭据、源文件未变化以及目标项目仍有效；目标数据库开始正常编辑后不能仅因其字节变化就判断迁移失败。不能证明已安全迁移的源文件保留待处理，目标盘不可用时停止删除。

每项删除记录结果，重试时已删除项可跳过，遇到同路径的新文件则保留。切换后的清理中断只恢复剩余清理，不能再从已部分清空的旧目录执行回滚。仍有用户文件的旧目录自然保留，不把目录尚在误报为迁移失败。

## 页面和日常操作

首页保持简单：顶部「新建项目」「打开项目」，下面是最近项目列表。项目列表展示名称、封面、最后打开时间和位置；导入项目包放在次级入口。暂不引入团队、空间或文件夹管理后台。

| 操作 | 建议行为 |
| --- | --- |
| 新建项目 | 只填项目名称；在统一保存目录下自动创建独立子目录，成功后进入画布 |
| 打开项目 | 选择项目文件夹并验证数据库；后续按需支持直接选择项目数据库 |
| 最近项目 | 点击打开；位置失效时提供「重新定位」「从列表移除」，不自动新建同名空项目 |
| 改项目名 | 修改项目内的展示名称；不静默修改目录名或搬动素材 |
| 在文件管理器中显示 | 定位真实项目目录，让用户知道数据在哪里 |
| 更改保存目录 | 在设置中迁移整个项目库，校验成功后统一切换，失败保持原位置 |
| 创建副本 | 只填副本名称，在统一保存目录下生成带独立项目 ID 的完整副本，成功后切换到副本；保留原项目 |
| 从最近列表移除 | 只移除索引，不删除项目文件；第一版不在列表提供永久删除项目 |

项目标题旁显示「保存中」「已保存」或可操作的保存失败状态。拖动结束、拼接、应用裁剪等已提交编辑写入数据库；文本草稿短暂防抖保存。`Cmd/Ctrl+S` 立即提交待保存修改。关闭或切换项目时等待保存结果；失败时保留当前项目及待保存内容，显示原因并允许重试，在成功落盘前不关闭项目或启动目录迁移，不假装已保存。

裁剪浮层的临时预览不自动覆盖已应用的裁剪参数；点击「应用」才提交，取消则丢弃临时变化。镜头编辑的草稿是否关闭即保留，仍需随编辑页面设计确认。

第一版建议一个窗口只编辑一个项目，同一项目只允许一个写入者。重复打开已打开的项目时聚焦原窗口；第二个应用实例也不能绕过项目占用检查。

## 素材保存与搬移

建议默认把导入素材复制到项目目录，生成结果先进入独立暂存区，由保存队列提交到项目目录。数据库用素材 ID 和相对项目根目录的路径关联，不依赖原始文件名或电脑上的绝对路径。同一项目可对相同内容去重。

这样关闭项目后搬动整个文件夹，或在另一台装有兼容版本软件的电脑上打开，素材引用仍可解析。具体格式能否解码和跨平台实际可用性仍需验证，不能仅凭路径能找到就宣称验证通过。

代价是导入需要复制时间和额外空间。第一版建议不暴露「仅引用原文件」选项，以减少素材丢失和搬移失败；以后如支持该模式，必须同时提供丢失素材重定位和「收集素材到项目」能力。

原始素材在项目中保持不可变，裁剪只存参数。新素材先写临时文件，完成后再进入正式目录并提交数据库引用；失败或崩溃后清理未完成文件。删除画布卡片不立即删除底层素材，避免破坏撤销、其他片段或候选版本。

日常更换存储位置使用设置中的完整迁移流程，不要求用户手动搬文件。手工备份或搬动项目文件夹前先关闭项目；再次打开时验证引用和位置。项目路径规范化后识别重复打开，不能仅凭项目 ID 将用户手动复制出的不同目录误判为同一个位置。

## 区分项目包与成片

| 入口 | 产物 | 用途 |
| --- | --- | --- |
| 导出项目包 | 数据库快照和完整项目素材组成的归档文件 | 备份、换电脑、交给别人继续编辑 |
| 导入项目包 | 自动解包到统一保存目录下的新项目子目录 | 恢复为可编辑项目 |
| 导出视频 | MP4 等媒体文件 | 播放和发布；不包含可编辑的项目结构 |

项目菜单提供「导入项目包／导出项目包」，视频导出明确标为「导出视频」，不把两种用途混成同一个含糊按钮。压缩包只作为搬运格式，编辑时解包到项目目录，不在压缩包内持续写数据库。

导入只选择来源项目包，不再询问项目保存位置。导出项目包或成片时仍可选择输出文件位置，用于备份和分享；输出位置不改变正在编辑的项目所在目录。

项目包默认包含保留的素材和候选版本；排除可重建的 `cache/`、应用设置、凭证、临时下载和项目外成片。已压缩视频以打包为主，不承诺明显缩小体积。导出前显示预计大小，缺失素材时提示修复，不把不完整项目标记为可完整恢复。

导入时在统一保存目录下创建独立副本并生成新项目 ID，保留镜头等项目内部关系，不覆盖已存在项目。先在临时目录解包、验证格式版本与素材清单，通过后才加入最近列表；失败可清理本次临时目录。归档中的绝对路径、向上越界路径、符号链接及不合理的解包体积需要拒绝。

## SQLite 与文件的一致性

SQLite 事务保护数据库内部更新，但不会把媒体文件的复制自动变成同一事务。需要由后台的项目存储模块一起处理数据库和素材生命周期，渲染界面只调用明确的项目操作。

编辑中的数据库不能直接当普通文件复制来完成「创建副本／导出项目包」。若启用 WAL，最近的提交可能仍在日志中；导出应先提交待保存修改，再通过数据库备份 API 获取一致快照。

导出以快照中的素材清单为准，保留这些不可变文件直到打包完成，避免快照后产生的素材清理让导出缺文件。导出期间的新编辑可留在原项目，不混入已选定的快照。输出先写临时文件，通过校验后再完成，取消不留下看似成功的项目包。

数据库结构升级前保留可恢复备份，事务化升级；旧软件遇到不认识的新格式时拒绝写入并提示升级。同一项目的写操作经统一队列执行，锁定与退出行为需经过异常退出测试。结构升级与保存目录迁移是两个独立操作，迁移目录时不顺便修改项目格式。

第一版以本机磁盘和稳定连接的外接盘为使用范围。网络共享目录、云盘多端同步中的活动数据库不在验证范围；WAL 不适用于不同主机通过网络文件系统协同访问，可配置保存目录不意味着支持多人同时编辑。

自动保存只解决及时落盘，不等同于历史版本或离线备份。保留多少历史快照、是否自动异地备份，后续单独设计；第一版先提供项目包和创建副本。

## 实现阶段与验收

项目首页、新建／打开、改名、保存状态和目录迁移已接入真实存储。项目包、完整项目菜单、数据库结构升级和备份仍按后续阶段推进；下面的总体验收项包含尚未实现的完整产品流程，不能直接当作当前版本验证清单。

- [ ] 新建、创建副本和导入项目包均自动使用统一保存目录，不逐个询问位置；同名项目不会互相覆盖。
- [ ] 同一保存目录下的多个项目内容互不影响；修改保存目录后全部受管项目迁移到新目录，项目 ID 和素材关系不变。
- [ ] 从最近列表移除的项目仍被迁移，外部打开的项目和原目录中的非项目文件不被擅自移动。
- [ ] 空间不足、目录不可写、同名冲突及路径嵌套在复制前被拒绝；活动写入停止后才复制数据库和素材。
- [ ] 切换前取消、断电、拔盘或复制／校验失败均不会提前切换路径或删除源数据；重启能识别迁移阶段。
- [ ] 切换事务前后分别异常退出，重启后仍能选择正确的完整项目库；清单过期时不会混用源文件的不同版本。
- [ ] 完成后最近项目、当前项目和后台任务均使用新路径；已验证的旧项目重复数据自动删除，未登记文件保持原样。
- [ ] 覆盖云端生成中、已完成待下载、下载中、结果登记中和迟到回调：成功切换后不写旧路径，取消则恢复原路径。
- [ ] 旧项目路径写入许可失效，项目句柄在复制前释放；向独立暂存区的下载仍可继续，连续迁移或重启恢复不会重新创建旧目录。
- [ ] 缓存文件和保存队列均持久化；重启和重复回调不会丢失结果、重复登记素材或自动重新发起付费生成。
- [ ] 检查迁移状态与取得保存许可不可交错出错，实际保存只使用当次有效路径；迁移无需等待全部云端任务结束。
- [ ] 缓存磁盘空间不足、目标保存失败及确认前崩溃不会清掉未交付结果；迁移清理和普通缓存清理不触及独立暂存区。
- [ ] 原根目录、项目子目录及素材／缓存目录里混入用户文件，清理均保留它们；同名替换、内容修改和符号链接不被误删。
- [ ] 清理前确认目标可用，切换前绝不删除源项目数据；可重建缓存和不可恢复的下载临时文件按各自规则处理。
- [ ] 删除权限不足、文件占用、清理中断或重启后显示真实待清理状态，可幂等重试，不回滚到已部分清理的旧目录。
- [ ] 保存目录不可写或未连接时有明确提示，不自动切换到其他位置保存。
- [ ] 重新打开后恢复片段顺序、画布布局、参考图、分镜文本和已应用裁剪。
- [ ] 保存失败／磁盘不足不会显示「已保存」，关闭或切换不会静默丢掉待保存编辑。
- [ ] 关闭后移动整个项目目录，再打开可恢复引用；移除最近记录不删除文件。
- [ ] 导入时原始来源文件被移动后，项目中的复制素材仍可用。
- [ ] 创建副本和项目包导入保留原项目，副本可以独立修改。
- [ ] 项目包包含快照对应的完整素材；导出时仍有编辑或后台下载也不破坏一致性。
- [ ] 异常退出、重复打开、迁移失败和较新格式有明确恢复或拒绝写入行为。
- [ ] 路径含中文／空格、外接盘断开、素材缺失和恶意归档得到明确处理。

## 已实现的代理缓存（2026-09-30）

代理记录存于项目 SQLite 的可选 `metadata.proxies` 中，包括素材 ID、源校验值、代理版本、相对路径和文件指纹；沿用 version 1 容器格式。成品在项目 `cache/proxy-v<版本>-<随机ID>.mp4`，重复进入编辑页复用，缺失后可重建。缓存随受管清单迁移并校验，切换成功后只删除身份与内容均符合清单的旧副本。用户在 `cache/` 另放的文件不加入清单；被删除或替换的代理不阻断迁移，也不会把替换文件纳入清理。

转码前在写入闸门保护下把源文件复制到固定的 `userData/preview-work/`，随后释放闸门。FFmpeg 只读独立副本，迁移无需等待整个转码；完成后通过可等待的闸门解析项目当前位置并发布、登记代理。临时输入／输出文件登记到应用数据库，正常结束、关闭及下次启动仅按登记路径和文件身份清理，不递归删除目录。代理可重新生成，与不可丢弃的生成结果 `staging/` 分开。

当前代理按进入编辑页的素材后台串行处理，单文件上限 256 MiB 并检查磁盘空间；未实现全库缓存容量管理或设置页手动清理。正式安装包的 FFmpeg 分发仍待确定，当前使用系统可执行文件或环境变量指定路径。
