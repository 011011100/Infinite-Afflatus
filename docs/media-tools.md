# 视频处理组件配置与诊断

更新时间：2026-10-05。

## 用户入口与范围

“设置 → 视频处理”可以分别选择本机 FFmpeg 与 FFprobe，先执行版本验证，成功才保存。取消选择、选错组件、文件被替换或保存失败都保留原配置。每个工具可单独恢复自动查找，不清除另一个工具的路径。

页面显示实际使用的路径或命令、配置来源，以及手动检查得到的版本、状态和时间。启动、打开设置和切换分类只读取配置，不运行检测；点击选择、恢复自动查找或“检查组件／重新检查”才启动版本检查。新设置立即对后续新任务生效，无须重启应用。

FFmpeg 负责成片编码与代理预览，FFprobe 读取媒体信息。项目管理、视频导入和原片播放仍可在缺少组件时使用；代理失败继续播放原片，导出失败保留错误任务并指向此设置入口。

当前应用未内置二进制，也没有确定的二进制分发来源。诊断不会自动下载、安装、修改环境、处理用户媒体或上传信息。版本检测仅确认程序能执行并返回正确名称的版本，不代表 libx264、AAC 编码器、参数版本或全部视频格式已经通过兼容性测试。

## 同一套路径解析

实际代理预览、成片导出与设置诊断共用 `src/main/media/media-tools.ts`：

1. 优先使用 `FFMPEG_PATH` 或 `FFPROBE_PATH`。值是可执行文件路径或命令名称，不是带参数的 shell 命令，不添加引号；明确配置不可用时直接报错，不自动改用其他工具。
2. 未设置环境变量时，使用应用内保存的绝对路径。保存前解析真实路径、核对普通可执行文件身份，并在验证后再次确认文件未变化。已保存路径失效会明确报错，不自动更换为另一版本。
3. 未保存路径时使用当前应用进程的 `PATH`。macOS 若当前 `PATH` 未找到可执行文件，再依次检查 `/opt/homebrew/bin` 与 `/usr/local/bin`。只选择真实存在、为普通文件且有执行权限的候选；不假定这些位置一定安装了组件。
4. 不扫描项目目录，不调用 shell，不更改系统或进程的环境变量。Windows／Linux 保留原有的系统命令查找，不猜测安装目录。环境变量指定某一工具时，该工具的应用内更改按钮禁用，并说明生效来源。

从 macOS Finder 启动的应用通常没有终端 shell 的环境配置，因此终端中可运行并不保证应用能找到自定义位置。用户可以直接在此页选择程序；只有修改启动环境变量时才需要重新启动应用。`pnpm doctor:media` 复用解析与检测实现，但只检查当前终端环境，不读取桌面应用保存的路径。

应用数据库新增独立设置 `mediaToolSettings`，格式为 `{ version: 1, ffmpeg: string | null, ffprobe: string | null }`。旧库缺少此键时保持自动查找，读取不补写。可解析 JSON 中的错误字段或不支持的版本保持原值，项目仍可打开；页面明确提供“清除两项路径并恢复自动查找”，只有此操作才重置两项路径。若应用数据库本身或设置的 JSON 语法损坏，仍按已有启动恢复规则阻止不安全打开，不能通过此页修复。配置不进入项目包，不改写项目、素材、代理缓存或导出任务格式。

## 失败与进程边界

读取、选择、重置和检测均通过类型化 preload 请求，只允许已验证的主窗口主 frame 调用。渲染进程仅传工具名称；路径来自主进程的原生文件选择器，保存前再次验证窗口身份。一次完整检测最多启动两个 `-version` 子进程，只有同一对工具的并发检测共用结果，旧检查不能覆盖新配置的显示。所有子进程关闭 shell 和输入，Windows 隐藏控制台。

每项检查最多 5 秒，标准输出与错误输出合计最多 64 KiB；超时或超量会终止检查进程。关闭应用会取消检查并等待子进程关闭，迟到的文件选择不能写入。缺少文件、权限不足、启动失败、无法识别版本及超时分别显示，不把空输出或返回非零状态当作成功。诊断结果仅保留在当前设置视图，数据库只保存所选路径。

每次导出开始、每项代理实际进入生成时，各自固定一对工具，输入探测、编码、拼接和输出验证始终使用该配置。排队代理开始时才读取最新设置，已有缓存命中不因当前配置损坏而失效。任务取消仍遵守已有 AbortSignal、临时文件和原子发布规则；诊断不占用项目写入通道。

## 验证边界

- `tests/media-tools.test.ts` 覆盖配置优先级、macOS 常见路径回退、正确工具身份、失败分类、超时终止、输出上限、按需检测与并发合并、命令不经 shell，以及实际导出子进程缺失时的提示。
- `tests/media-tool-settings.test.ts` 与 IPC 回归覆盖真实 SQLite 持久化、损坏配置保留、路径身份、取消／错误／写入失败及关闭等待；`tests/media-task-tools.test.ts` 覆盖修改配置期间的任务固定、排队与缓存行为。
- 隔离 React 夹具使用模拟 IPC 验证交互；`tests/browser/media-tool-settings-desktop.cjs` 用真实生产主进程／preload／页面、SQLite 和三个独立进程验证选择、重开、单项重置与损坏配置修复。只提供原生选择器返回值，版本程序由测试生成并真实运行，不具备媒体编码能力。
- `pnpm doctor:media` 通过只能证明当前终端可找到并启动两个组件，不能证明打包后 PATH、签名／系统权限、所有编码器或所有媒体格式。真实 FFmpeg 媒体回归另行执行。
- 正式安装包、Windows、真实云端 API 和二进制分发许可需要各自独立验证。

实现依据：[Node.js 子进程接口](https://nodejs.org/api/child_process.html) 的直接启动及环境路径行为、[FFmpeg 通用选项](https://ffmpeg.org/ffmpeg.html#Generic-options) 的 `-version` 说明。
