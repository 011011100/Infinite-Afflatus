# 视频处理组件诊断

更新时间：2026-10-05。

## 用户入口与范围

“设置 → 视频处理”可以检查本机 FFmpeg 与 FFprobe，显示是否能够运行、版本、使用的路径或命令、配置来源及检查时间。检查只在点击“检查组件／重新检查”时执行，不会在启动、打开设置或切换分类时自动运行。

FFmpeg 负责成片编码与代理预览，FFprobe 读取媒体信息。项目管理、视频导入和原片播放仍可在缺少组件时使用；代理失败继续播放原片，导出失败保留错误任务并指向此设置入口。

当前应用未内置二进制，也没有确定的二进制分发来源。诊断不会自动下载、安装、修改环境、处理用户媒体或上传信息。版本检测仅确认程序能执行并返回正确名称的版本，不代表 libx264、AAC 编码器、参数版本或全部视频格式已经通过兼容性测试。

## 同一套路径解析

实际代理预览、成片导出、设置诊断及 `pnpm doctor:media` 共用 `src/main/media/media-tools.ts`：

1. 优先使用 `FFMPEG_PATH` 或 `FFPROBE_PATH`。值是可执行文件路径或命令名称，不是带参数的 shell 命令，不添加引号；明确配置不可用时直接报错，不自动改用其他工具。
2. 未配置时使用当前应用进程的 `PATH`。
3. macOS 若当前 `PATH` 未找到可执行文件，再依次检查 `/opt/homebrew/bin` 与 `/usr/local/bin`。只选择真实存在、为普通文件且有执行权限的候选；不假定这些位置一定安装了组件。
4. 不扫描项目目录，不调用 shell，不更改系统或进程的环境变量。Windows／Linux 保留原有的系统命令查找，不猜测安装目录。

从 macOS Finder 启动的应用通常没有终端 shell 的环境配置，因此终端中可运行并不保证应用能找到自定义位置。用户可按设置页高级说明配置两个工具的完整路径；安装或更改配置后重启应用，再检查。

## 失败与进程边界

检测通过类型化 preload `checkMediaTools()` 请求，只允许已验证的主窗口主 frame 调用，不接收渲染进程提供的路径或任意命令。一次请求最多启动两个 `-version` 子进程，并发请求共用当前检查。所有子进程关闭 shell 和输入，Windows 隐藏控制台。

每项检查最多 5 秒，标准输出与错误输出合计最多 64 KiB；超时或超量会终止检查进程。缺少文件、权限不足、启动失败、无法识别版本及超时分别显示，不把空输出或返回非零状态当作成功。诊断结果只保留在当前设置视图，不新增数据库字段或长期缓存，重新检查会读取当前状态。

实际媒体任务使用相同解析与启动失败提示。取消任务仍遵守已有 AbortSignal、临时文件和原子发布规则；诊断不持有项目写入 gate。

## 验证边界

- `tests/media-tools.test.ts` 覆盖配置优先级、macOS 常见路径回退、正确工具身份、失败分类、超时终止、输出上限、按需检测与并发合并、命令不经 shell，以及实际导出子进程缺失时的提示。
- `pnpm doctor:media` 使用同一真实子进程检测。通过只能证明当前运行环境可找到并启动两个组件，不能证明打包后 PATH、签名／系统权限、所有编码器或所有媒体格式。
- 正式安装包、Windows、真实云端 API 和二进制分发许可需要各自独立验证。

实现依据：[Node.js 子进程接口](https://nodejs.org/api/child_process.html) 的直接启动及环境路径行为、[FFmpeg 通用选项](https://ffmpeg.org/ffmpeg.html#Generic-options) 的 `-version` 说明。
